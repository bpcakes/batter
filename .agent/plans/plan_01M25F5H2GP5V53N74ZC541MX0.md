## Surprises & Discoveries

The review's request-span issue is only half the correlation loss. crates/batter/src/telemetry.rs parents operation events to its own disabled INFO span, even if a request parent is enabled. Native Span::or_current is already used by HTTP/task instrumentation but missing from operation observation. Merely changing the HTTP target leaves WARN operation failures uncorrelated. Existing Startup ownership is correct: borrowed wait cancellation is inert; dropping StartingSupervisor requests drain and its coordinator drops the supervisor (releasing registered listener captures) before awaiting cleanup. Existing abandoned-startup test only drops an inert Supervisor.

## Decision Log

Separate observation-owned span fields from retained execution/event context. Capture fallback once, not at destruction, and never record operation fields onto application spans. Use the existing native Span pattern, not a new global context framework. Retain HTTP UUID fields directly on events for filters that disable every INFO span. Use static target batter::request and document info,batter=warn,batter::request=info: static target specificity retains context without enabling unrelated nested INFO events. Span-name directives can dynamically enable nested events and are unsuitable for this quiet mode.

Keep register_http a plain-Router helper; ConnectInfo requires native into_make_service_with_connect_info and an application-owned serve closure. Do not generalize the helper into a server framework. Keep ReadinessReason exhaustive intentionally: adding policy states requires coordinated consumer review; adding non_exhaustive now is itself an API change and wildcard fallbacks can hide new health decisions. The prior streaming regression proves body lifetime exclusion and wrapper-abort limits, not remote cancellation. No runtime redesign is justified by the ownership test omission.
