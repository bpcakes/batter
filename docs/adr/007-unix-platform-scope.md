# ADR-007: Unix-only platform scope

Status: accepted. Date: 2026-09-08.

Context: this workspace provides native Tokio backend lifecycle and process
contracts. Platform fallbacks add different signal and termination semantics
to maintain and test. The project owner has explicitly excluded Windows from
both current support and future plans.

Decision: target Unix systems, including Linux and macOS, across all workspace
packages, examples, tests and tooling. Windows is unsupported and has no planned
support. Use native Unix signal registration and process exit status directly.
Do not add Windows
branches, non-Unix fallback implementations, compatibility layers, or CI jobs.
Keep the policy visible in the root README/AGENTS, package guides and rustdoc.

Linux x86_64 and macOS arm64 have executed the full verification matrix and
rebuilt HTTP smoke tests on Rust 1.94.0 and 1.98.1 (HTTP uses 1.98.1). This host
evidence is separate from the updated macOS CI job, which has not run yet. Other
Unix systems remain unverified; scope does not imply validation on every target.

Consequences: example shutdown registers SIGINT/SIGTERM listeners directly,
acknowledging readiness only after registration succeeds. The subprocess
watchdog distinguishes a kill request from an observed SIGKILL exit status,
with no alternative interpretation based on a platform-specific numeric exit
code. These existing failure contracts remain covered by the Unix tests.

Generic library code may incidentally compile on other targets; that does not
establish support. Cargo.lock remains generated by Cargo, including upstream
target-specific dependency entries. Do not edit the lockfile to remove those
entries or import their platform support into this project's commitments.
See [testing](../testing.md), [status](../status.md) and
[validation](../validation.md) for checks and their limits.
